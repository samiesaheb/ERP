# Skyhigh MES/ERP

An integrated Manufacturing Execution System and Enterprise Resource Planning application built for **Sky High International Co., Ltd.** — a cosmetics and personal care manufacturer based in Thailand.

The system covers the full production lifecycle: sales orders, formulation management, bill of materials, procurement, inventory, manufacturing, shop floor execution, shipments, and finance — with a complete audit trail on every write.

---

## Tech Stack

| Layer | Technology |
|---|---|
| **API** | Rust · Axum 0.7 · Tokio (async runtime) |
| **Database access** | SQLx 0.8 (compile-time checked queries) |
| **Frontend** | Next.js 16 (App Router) · React 19 · TypeScript |

| **Database** | PostgreSQL (UUID primary keys throughout) |
| **Auth** | JWT (`jsonwebtoken`) · bcrypt password hashing |

## Modules

| Module | What it does |
|---|---|
| **Dashboard** | KPI summary — open orders, batches in progress, inventory alerts |
| **Items** | Master item catalogue — `FG` (finished goods), `RawMat`, `PackMat` |
| **Formulations** | Cosmetic recipes: INCI ingredient list, % w/w per phase, batch size |
| **BOM** | Bill of Materials per product version — component quantities, routing steps |
| **Sales Orders** | Customer orders with line items, artwork tracking, FDA registration status |
| **Procurement** | Purchase orders and goods receipt notes (GRN) linked to suppliers |
| **Inventory** | Stock balances by item/location/lot, transaction ledger, cycle counts |
| **Warehouse Locations** | Rack/bin location master with zone and aisle structure |
| **Manufacturing Orders** | Production orders linking sales orders → BOM → planned quantities |
| **Production Batches** | Batch-level execution: Bulk → Fill → Pack stages with timestamps |
| **Shop Floor** | Work centres, QC tests, downtime events, component issue tracking |
| **Shipments** | Outbound shipments with line items and shipping documents |
| **Finance** | Invoices, invoice lines, payments (customer and supplier) |
| **Audit Trail** | Immutable log of every INSERT/UPDATE/DELETE on all major tables |
| **Global Search** | Cross-entity search across items, orders, batches, customers |
| **Access Requests** | Role elevation requests with review workflow |
| **MRP** | Material requirements planning periods and item planning data |

## Database

**44 tables · 112 indexes (all B-Tree) · 17 migrations · 32 audit triggers**

Every table uses a `UUID` primary key generated by `uuid_generate_v4()`. No serial integer sequences are used.

An `audit_trigger` fires `AFTER INSERT OR UPDATE OR DELETE` on 32 tables and writes a full JSON snapshot of the old and new row into `audit_logs`. The API layer injects the current user's UUID via `SET LOCAL app.current_user_id` so every audit entry is user-attributed.

Key column types: `uuid` (128 columns), `text` (109), `timestamptz` (53), `numeric` (37 — all financial and quantity fields), `jsonb` (audit snapshots), `boolean`, `integer`, `date`.

Foreign key cascade rules: child rows cascade-delete when a parent `bom`, `formulation`, `invoice`, `fda_registration`, or `production_batch` is deleted. All other foreign keys use `NO ACTION` (reject delete if children exist).

## Getting Started

### Prerequisites

- Rust (stable, 1.87+)
- Node.js 20+
- PostgreSQL 15+

### 1. Database

```bash
createdb skyhigh_mes
psql skyhigh_mes -c 'CREATE EXTENSION IF NOT EXISTS "uuid-ossp";'
```

### 2. API

```bash
cd api
cp .env.example .env          # set DATABASE_URL and JWT_SECRET
cargo run
# API starts on http://localhost:8080
```

Run migrations (handled automatically on startup via SQLx migrate):
```bash
cargo sqlx migrate run
```

### 3. Frontend

```bash
cd web
npm install
# .env.local already points to http://localhost:8080
npm run dev
# UI starts on http://localhost:3000
```

### Environment Variables

**`api/.env`**
```
DATABASE_URL=postgres://localhost/skyhigh_mes
JWT_SECRET=<your-secret>
```

**`web/.env.local`**
```
NEXT_PUBLIC_API_URL=http://localhost:8080
API_URL=http://localhost:8080
```

## Deployment

The API is deployed to **Railway** using nixpacks. The `railway.toml` configures the build command (`build.sh`), start command, and health check at `/health`.

Docker multi-stage build:
```bash
docker build -t skyhigh-api ./api
docker run -e DATABASE_URL=... -e JWT_SECRET=... -p 8080:8080 skyhigh-api
```

## Data Import

Reference Excel files from the factory are located in `documents/`:

- `record daily data production report.xlsx` — live packaging material inventory ledger and production batch tracking (Khun Nut)
- `VY-01.1 Avocado Oil 100% Pure Moisturizing Oil _CFUp_16.2.2021.xlsx` — Master Formula for product VY-01/1 (Khun Tik)

These map to the following tables in the schema:

| Excel data | Database tables |
|---|---|
| Incoming materials (INCOMMING sheet) | `items` (PackMat), `suppliers`, `receipts`, `receipt_lines` |
| Material balances | `inventory`, `inventory_transactions` |
| Rack locations (Dep. column) | `warehouse_locations` |
| Production batches (FG sheet) | `manufacturing_orders`, `production_batches` |
| Loss columns | `batch_component_issues` |
| Master Formula ingredients | `ingredients`, `formulations`, `formulation_lines` |
| Master Formula product | `items` (FG), `boms`, `bom_lines` |
